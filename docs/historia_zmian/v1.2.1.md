# v1.2.1 — naprawa błędu kompilacji Kotlina w NativeTtsBridge.kt

## Błąd
Budowanie kończyło się błędem:
`The feature "unit conversions on arbitrary expressions" is experimental...`
w pliku `NativeTtsBridge.kt`, linia z `synchronized(pending) { pending.add(run) }`.

**Przyczyna:** funkcja `val run = { ... }` nie miała jawnie zadeklarowanego typu.
Kompilator wywnioskował go z ostatniej instrukcji w bloku (`tts?.speak(...)`, zwracającej
`Int?`), więc `run` miał typ `() -> Int?`. Lista oczekujących wywołań `pending` jest
typu `MutableList<() -> Unit>` — dodanie do niej wartości `() -> Int?` wymaga niejawnej
konwersji na `Unit`, a taka konwersja dla zmiennych (w odróżnieniu od literałów lambda
podawanych bezpośrednio jako argument) jest w Kotlinie funkcją eksperymentalną i nie
kompiluje się bez jawnego włączenia.

## Poprawka
Dodano jawny typ `val run: () -> Unit = { ... }` oraz `Unit` jako ostatnią instrukcję
bloku — dzięki temu typ jest zgodny od razu, bez potrzeby żadnej konwersji.

## Plik zmieniony
- `android/app/src/main/java/pl/linguaforge/app/NativeTtsBridge.kt`
